# EDA report deck — surface brief

Mode: Read. The visitor understands something; the deck is a report, not a pitch.

Audience and job: the CSC 173 instructor and classmates, in a classroom or on a shared screen. The reader asks three questions in order: is this data trustworthy, what does each finding mean, and what carries into modelling. The deck answers in that order and refuses any claim the corpus cannot support.

Proof and content: the ScreenSpot-Pro release (Li et al., 2025), fetched with `python -m isdm.data.fetch`, cleaned by `src/isdm/eda`, reported in `notebooks/EDA_Beira_John-Ronan.ipynb`. Every figure is generated by `presentation/eda/scripts/build_figures.py`, which asserts each headline number against the table before it draws. Ten slides: cover, corpus, quality, cleaning, and five findings, closing on four decisions. Captions are sentences that name their own sample, and no slide cites a path a reader cannot open.

Constraints: static HTML/CSS/JS, no build step, GitHub Pages at `/eda/`. The existing `presentation/` deck moves to `/pitch/` and must not change in appearance or behaviour. Wording follows ASD-STE100: short sentences, active voice, one idea per sentence. Numbers are the ones counted, never rounded into a different claim.

## Direction contract

THESIS: this deck is a measurement printout, not a magazine spread. It refuses both the equal-card grid and the headline-plus-sidebar layout; every finding gets one screen in a fixed reading order — heading, note, numbers, chart, caption — and the slide that cannot support a claim says so in amber.

OWN-WORLD: the CRT-phosphor terminal already recorded in `presentation/DESIGN.md` — near-black glass, phosphor green for measured values, dim phosphor for bulk marks, amber for a boundary, a limit or a blocked claim, 1px rules, square panels, Saira Condensed for the claim and JetBrains Mono for the evidence. This surface adds only two patterns: a single-column reading order (heading, one-line note, number strip, figure, caption) and a row set carrying a count, a statement and a state tag.

STORY: the reader sees 1,020 requests, learns the merge is exact and the repairs counted, then reads five findings that each hold under a stated limit, and leaves with four rules and the sentence that the corpus has no outcome labels.

FIRST VIEWPORT: a four-line uppercase claim on the left — the median target covers 0.0382% of the screen — with the corpus check panel on the right, replaying five counted lines in sequence behind a `[ RUN ]` control. The status chip says "Measured / the release has no outcome labels".

FORM: seed: none (pinned). The user pinned the world by pointing at the existing records: "Those markdown files already exist in @folder:presentation" and the recorded commitment "the user pinned the CRT-phosphor visual world". No new identity is derived; the deck extends the recorded system and inherits its motion policy.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance.
